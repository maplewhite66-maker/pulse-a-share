# Pulse A股智能动态盯盘系统 4.0

线上入口：https://pulse-a-share-production.up.railway.app/

手机盘前报告：https://pulse-a-share-production.up.railway.app/#premarket

部署在 Railway，由同一个 FastAPI 服务提供网页、HTTP API、WebSocket 与盘前调度。手机无需与电脑同一局域网；电脑关机不影响云端服务。实际运营商网络可达性仍需在手机上验证。

## 运行能力

- 指数与自选报价：腾讯财经，按交易阶段调整频率，多客户端合并上游请求。
- 日/周/月及分钟K线：腾讯三个入口，复权选择、价格与成交量、MACD/RSI；科创板与普通股票的成交量单位分别处理。
- 板块资金TOP20：东方财富行业/概念/地域，当日/5日/10日；净流入或净流出榜。接口可能切换到明确标注的延时入口，日期缺失时显示“未提供时间”。
- 自选股：保存在当前手机/浏览器本地，可导入导出。不同设备不会自动同步。
- 异动预警：网页开启时扫描自选，提供阈值、声音和浏览器通知选项。没有配置网页关闭后的手机推送。
- 盘前报告：美股指数、股指与商品期货、国际新闻、行业线索、12只样本股的机会观察池与风险条件。
- 旧版模拟账户保留在本地版；公网服务拒绝读取个人模拟账本，真实行情API拒绝 demo 模式。

## 数据来源与限制

| 数据 | 取数方式 | 时间与口径 |
|---|---|---|
| A股报价与K线 | a-stock-data 3.10.4 §1.1/§1.2 对应的 HTTP 采集代码，经 `backend/adapters/live.py` 封装 | 分别显示源端行情时间、采集时间、缓存与失败状态 |
| 板块资金/个股资金 | a-stock-data §3.8/§3.4，东方财富 | 串行限流、最小间隔加抖动、失败冷却；不虚构主力资金 |
| 交易日历 | 深交所整月日历，a-stock-data §12 | 检查月份、日期完整性和交易标志；不把普通工作日当作已确认交易日 |
| 美股与期货 | Yahoo Finance chart；美股三大指数另接新浪 | 美股按美东日期确认收盘；期货按上一日线收价计算涨跌；可能延迟 |
| 商品与A50 CFD | 新浪行情，沿用 a-stock-data §13 的行情解析方式 | CFD独立命名、独立单位；不替代交易所期货合约；铜CFD单位为美分/磅 |
| 国际新闻 | a-stock-data §5.4，华尔街见闻全球快讯 | 上一日15:00至实际采集时点，最多4页400条，最多展示15条匹配结果，标明窗口是否完整 |

Skill来源：https://github.com/simonlin1212/a-stock-data 。这是结构化 Markdown 与内嵌 Python 能力文档，不是独立统一REST API。本项目保留 Apache-2.0 许可与来源标识。没有配置 iFinD 付费数据凭据。

缺失数值以空值呈现，失败后只回退到标明时间的真实缓存。未验证、过期、未来时间或异常格式的数据不进入方向判断。不使用随机行情填充真实接口。Yahoo 429 会触发15分钟全局冷却；其他来源按各自缓存和限流策略读取。

## 每日08:00报告

`backend/services/premarket.py` 中的常驻任务使用 `Asia/Shanghai`。每分钟检查一次，在官方确认的A股交易日08:00开始生成，通常在取数完成后数十秒内可读。数据不齐时仍明确显示部分报告；日历无法确认时保留错误并重试。

服务在08:00后启动时，09:15之前可补生成；08:05后生成会标注实际时点，不声称是08:00历史快照。09:15以后不补造盘前报告。系统需要 Railway 服务持续运行、账号资源可用和上游可达，无法承诺上游数据每次齐全。

SQLite持久卷存放报价缓存、报告与历史。原报告保留；管理员可通过命令生成补充版本，旧版通过 `?revision=1` 查询或导出。报告提供SHA-256文本校验值。`PULSE_BOOTSTRAP_REPORT` 只用于一次性同步校验过的真实报告，保留生成/源端时间并显示同步来源；它不会给行情API提供数据。

2026-11-11首份报告在部署过程中补生成；开发环境取回更完整的真实外盘数据后同步补充版本。后续每日任务由云端直接取数。

观察池固定为工业富联、宁德时代、比亚迪、寒武纪、贵州茅台、平安银行、紫金矿业、中国石化、中际旭创、万华化学、中国船舶、恒瑞医药。过滤ST/退市标签、时间不符、流动性不足与不满足均线条件的标的。规则分不是胜率，筛选范围不是全市场。行业影响以规则推断呈现。

## 收盘复盘游资龙虎榜

「收盘复盘 → 每日游资龙虎榜」显示最新归档，可按交易日查找，下载 PNG 或 SVG，并从完整席位明细打开个股图表。归档保留最近 120 个有数据的交易日。

- 北京时间交易日 17:00 开始生成，18:30 和 20:30 再核对。遇到披露延迟或上游故障，22:00 前每 5 分钟重试，并保留上次有效归档。
- 汇总按上榜日期、股票、披露编号及原始席位名称对齐。每只股的单日和累计类别各选一条披露记录，优先选择两侧记录较齐全、榜单成交额较大的记录。顶部只统计单日披露的席位净额，三日及其他累计披露单列。营业部简称仅用于展示。
- `GET /api/reports/daily-lhb?day=YYYY-MM-DD` 返回报告与归档日期，省略日期读取最新归档。图片接口为 `GET /api/reports/daily-lhb/YYYY-MM-DD.svg`。
- 任务默认沿用 `PULSE_SCHEDULER`，可用 `PULSE_LHB_SCHEDULER` 单独开启或关闭。榜单保存到现有数据库的独立归档键。

## 本地启动

Windows安装 Python 3.11+，双击 `启动盯盘台.bat`。旧版完整说明见 `README-legacy.md`，以本文件的3.0行为为准。

```bash
python -m pip install -r backend/requirements.lock
python -m backend.launch
```

默认只接受本机同源访问。网页默认真实模式；本地版可明确切换到离线演示，演示数据使用单独缓存空间。

重新编译前端需要Node 22：

```bash
npm ci --prefix frontend
npm run build --prefix frontend
```

## Railway部署

Docker多阶段构建前端，安装已测试的Python锁定依赖，启动 `python -m backend.serve`。启动时仅初始化持久卷文件权限，随后降权为UID/GID 10001运行；API进程不以root运行。

1. `railway up -y` 上传源码。
2. 持久卷挂载 `/data`，容量500MB；单副本运行。
3. 配置下面的环境变量。
4. 配置公开域名转发容器8080端口，健康检查为 `/healthz`。
5. `.railway/railway.ts` 管理构建、健康检查、关闭休眠、重启策略和卷，`railway config plan` 审查后再 `railway config apply`。

| 环境变量 | 云端值 |
|---|---|
| `PORT` | `8080` |
| `PULSE_ACCESS` | `cloud` |
| `PULSE_DB` | `/data/market.db` |
| `PULSE_SCHEDULER` | `1` |
| `PULSE_ALLOWED_HOSTS` | `pulse-a-share-production.up.railway.app`，自定义域名需加入此列表 |
| `PULSE_EM_INTERVAL` | `1.6` |

基础设施源码使用Railway IaC，不依赖将于2026-12-01停用的 `railway.json`。环境变量由服务端管理，源码不含账号令牌或密钥。服务与持久卷会使用Railway账号资源，费用按账号套餐计算；本次没有升级套餐或添加付费数据订阅。

## 3.1：09:15竞价观察与全天云端策略

新增 `/api/monitor/status`、`/api/monitor/events` 与手机 `#monitor` 页面。`PULSE_MONITOR=1` 开启后台任务；`PULSE_MONITOR_CODES` 用逗号配置云端观察代码，最多60只。当前云端为原12只样本加万向德农、郑州煤电，且自动合并当日已产生的开盘/尾盘候选。它与手机浏览器本地自选分开存放，不会自动覆盖本地列表。

交易日09:15–09:25分开展示普通报价和通过源端时间校验的虚拟撮合快照；竞价只观察。09:25–09:30等待开盘；09:30–10:00原开盘量价候选继续扫描。全天对指数、样本、板块资金与异动进行跟踪，目标报价周期8秒、板块90秒，实际耗时受上游响应影响。午间及休市暂停报价扫描，已有小时筛选与收盘复核独立运行。

页面显示计划09:15、实际首次扫描时间、心跳、有效报价数和失败原因。当天在09:15之后才部署时，只记录实际启动时点，不回填或伪造已错过的竞价记录。任务在网页关闭后继续运行；浏览器通知仍只在页面打开并获授权时可用，没有配置手机后台推送。程序没有真实委托接口。

本次新增测试覆盖竞价观察不生成买入信号、假日/日历失败/午间暂停、8秒扫描与板块节流、收盘竞价停止新增信号、重启保留实际启动时间、旧指数不生成方向判断。后端共65项通过；前端生产编译通过。

### 个股主力资金与真实竞价

- 「全天盯盘 → 云端观察池 → 查看资金」打开个股分时资金详情。`/api/stocks/{code}/fund-flow?span=minute` 从东方财富延时入口以 `lmt=0` 取全天序列，`f52` 是当日累计主力净额，`f55` 和 `f56` 分别是大单与超大单净额，单位元。需要计算某段流量时用两个累计点相减。日级查询的每行代表独立交易日。
- 页面标示源端时间、交易日期、分钟数、是否完整和延时入口。午休、盘前上一交易日收盘、滞后缓存、非预期交易日和断源各有状态。跨日混合的分时序列、代码或市场不符的响应会被拒收。
- 后端可使用[同花顺扶摇竞价接口](https://fuyao.aicubes.cn/docs/api-reference/auction/)。只在服务端配置 `PULSE_FUYAO_API_KEY`。`PULSE_FUYAO_QUOTE_TIME_FIELD` 指向供应商确认的真实行情时间字段，须含交易日期，且与交易窗口、响应组装时间一致。`data.timestamp` 是组装时间，单独使用时行情不可验。只有供应商授权公网展示时才设置 `PULSE_AUCTION_PUBLIC=1`。
- 虚拟撮合价、撮合量和未撮合量必须来自 `stage=live` 的同日有效快照。过期快照只可作为历史记录。09:25最终撮合尚无独立验收数据。本增量源码仍待使用已有生产服务授权发布，并在交易日09:15–09:25用真实时标验收。

## 每日交易复盘

进入「交易复盘」可按北京时间交易日查看已登记成交和当日记录后持仓。用户提供的持仓成本保留三位小数，手续费未单列的记录显示为「持仓成本」。导入预览经用户保存后写入当前浏览器的真实账本，可重复打开同一导入链接，已有记录会跳过。

导入参数位于 URL 片段，浏览器不会随 HTTP 请求发送该片段。保存成功后页面移除片段，持仓留在当前浏览器内。不同浏览器使用各自的账本。

## 云端模拟交易执行

云端设置 `PULSE_PAPER_CLOUD=1` 后启动同一套模拟交易策略，模拟账户写入持久卷中的 SQLite。账户明细仍由公网中间件隔离，公开配置仅返回运行开关和最近轮询时间。运行日志记录初始账户状态和每轮执行结果。
